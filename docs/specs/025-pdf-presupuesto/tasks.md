## Convención

- Cada tarea completable y verificable en una sesión.
- Se marca `[x]` solo cuando cumple la Definición de «Done»: compila, tests en verde, mutaciones detectadas, comprobado en vivo y manual al día.
- **Nivel de riesgo de las pruebas: alto.** Es un fichero que **sale de la plataforma** con datos fiscales, datos de un cliente y dinero, generado a partir de texto libre. Se aplica la batería completa: el contenido leído **de vuelta del PDF** (no solo «no falla»), los **15 casos fijos de totales** de la spec 023 comparados con la API, texto hostil, el PDF inerte, la matriz de roles con control positivo, el aislamiento entre empresas, el límite de peticiones, escaneos de arquitectura y mutaciones sobre lo que decide.
- Las mutaciones se hacen a mano sobre el código real, con copia de seguridad y **`touch` al restaurar**; solo cuenta como «detectada» una con tests en rojo (`[FAIL]`); un test colgado o un error de compilación no cuentan. **Una mutación debe quitar de verdad lo que dice quitar.** Los guiones van **en ficheros** (nunca en `node -e` con comillas invertidas dentro). **No lanzar dos bucles de mutaciones a la vez.**
- Las suites se lanzan **por proyecto, una detrás de otra**. Si `dotnet build` choca con una DLL bloqueada, se compila a una carpeta aparte con `-p:OutDir` y no se mata el proceso que la tiene.
- El **texto de un PDF se lee de vuelta con PdfPig** (Apache-2.0, solo en los proyectos de test). Un PDF se comprueba por su contenido, nunca por sus bytes (llevan identificadores y fechas).
- Verificación en vivo con la receta de siempre (base desechable, API real, y en el bloque 3 `ng serve` y el navegador integrado). Los valores de prueba se generan en ejecución.
- **Dependencias nuevas** (ADR-010): versión con más de tres meses de antigüedad, licencia comprobada **en el `.nuspec`** (no en el README) y `NuGetAudit` limpio.
- **Orden de entrega:** el backend **puede fusionarse solo** (una operación nueva; no cambia nada existente). El frontend va en el mismo par de PR por limpieza. La rama parte de `spec/024-company-profile`: **si el PR #66 sigue abierto, el PR de esta spec lo apila encima** (base `spec/024-company-profile`) hasta que se fusione.
