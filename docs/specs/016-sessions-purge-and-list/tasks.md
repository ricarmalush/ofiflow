### Bloque 2 — Los datos de la sesión (Application + Infrastructure, con migración)
- [x] Migración `AddRefreshTokenSessionInfo`: `CreatedAt` (relleno `DATEADD(DAY, -7, ExpiresAt)`), `SessionStartedAt` (= `CreatedAt`), `UserAgent` (256) e `IpAddress` (45), anulables. Mismo patrón de la spec 015: EF generaba las dos fechas con 0001-01-01 por defecto; se crean anulables, se rellenan y solo entonces pasan a `NOT NULL`, sin valor por defecto. Probada con filas de la migración anterior, con filas creadas por la **versión anterior de la API** y con el `Down` con datos dentro
- [x] `IClientInfo` (Application) y `ClientInfo` (Infrastructure, la única puerta de esos dos datos): IP truncada (IPv4 sin el último octeto; IPv6 a 48 bits; IPv4 mapeada tratada como IPv4; zona IPv6 descartada; loopback tal cual, por no ser un dato personal; sin dirección = nulo) y `User-Agent` sin caracteres de control, recortado a 256 sin partir una pareja de sustitución, sin interpretar. `IClientInfo` es dependencia **obligatoria** de `TokenService`: que falte el registro no debe guardar «nada» en silencio
- [x] `TokenService.IssueTokensAsync` estampa `CreatedAt`, `SessionStartedAt` (un único instante), el navegador y la IP truncada; `RotateRefreshTokenAsync` **hereda** `SessionStartedAt`, navegador e IP de la fila anterior y toma su propio `CreatedAt`
- [x] Tests (47): el truncado (IPv4, IPv6, mapeada, zona, loopback, nulo, 500 direcciones aleatorias de cada familia sin que salga nunca la completa) y el saneado del navegador (nulo, solo control, inyección, tope exacto, enorme, pareja de sustitución) — 29; estampar y heredar (la renovación desde otro navegador o red no cambia el dispositivo, muchas renovaciones, una sesión sin datos no se inventa uno, cada login su propio inicio) — 7; persistencia con SQL Server real (ida y vuelta, nunca una fecha del año 1, los valores más largos caben, la base rechaza lo que se pasa del tope, **el esquema resultante de la migración**) — 5; de punta a punta en la API real (la IP truncada y el navegador de la petición llegan a la fila, la IP completa no se guarda en ninguna fila, renovar desde otro cliente no cambia el dispositivo, un navegador enorme se recorta y el login sigue, sin cabecera de navegador) — 6
- [x] Mutaciones (15, todas detectadas): no truncar IPv4; conservar 64 bits de IPv6; no tratar la IPv4 mapeada; no respetar el loopback; no quitar caracteres de control; tope 257; partir la pareja de sustitución; no recortar espacios; no estampar el navegador; no estampar la red; no heredar el inicio; heredar el navegador del cliente actual en vez del de la fila; heredar el `CreatedAt`; un inicio distinto de la creación; y quitar el registro de `IClientInfo` (la detecta la API)
- [x] Verificación contra la API publicada de verdad (base desechable): dos sesiones creadas por la versión anterior sobre el esquema anterior; la migración aplicada encima (`CreatedAt = ExpiresAt − 7 días` en las dos, `SessionStartedAt = CreatedAt`, sin navegador ni red, ninguna fecha del año 1, esquema `NOT NULL` y sin valor por defecto); la versión nueva renueva una sesión anterior **sin inventarle un dispositivo** (el cliente que renueva dice «Curl» y no se guarda) y conservando cuándo empezó; un login nuevo guarda el navegador y la red; renovarlo desde Firefox sigue diciendo Chrome; y el `Down` deshace las columnas sin perder filas
